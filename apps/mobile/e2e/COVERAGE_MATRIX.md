## 3.1 Profondeur des cas — COACH _(jusqu'où pousser V/E/O/P)_

**Doctrine (pour ne pas re-tester 18× le même pattern) :**

- **N est toujours à fond** + assertion **Effet** (re-fetch) sur toute mutation. C'est le cœur.
- **E (erreur serveur générique)** = toast + retry : pattern **partagé**, testé **à fond une seule fois** par statut (401/403/404/422/429/500) dans `cross-rbac-errors`. Par écran → simple **smoke** via la convention `*-error/-retry`. **Exceptions poussées** : régression « dist périmé » sur Groupes (liste), et le **mapping 422** de `createSession` (assistant).
- **O (offline)** : le coach est **lecture-dominante** → un seul test de **bandeau hors-ligne** au transverse. Pas de O par écran coach (le O profond vit côté athlète : brouillon de perf).
- **P (RBAC)** = 2 couches : (a) **séparation de rôle** (athlète n'entre pas dans `(coach)`) testée 1× au layout + transverse ; (b) **cloisonnement multi-coach (ADR-51)** poussé sur **chaque GET sensible** (athlètes, détail athlète, détail groupe) car c'est un vrai risque de fuite de données.
- **V (validation champ)** profonde uniquement sur **assistant** + **builder** (logique métier réelle) ; ailleurs un cas représentatif suffit.
- **∅ / L** : pilotés par convention (`*-loading/-empty`), **une** assertion par écran, sans variantes.

**Légende profondeur** : ◆ à fond (variantes multiples + Effet) · ● un cas représentatif (+Effet si mutation) · ○ smoke via convention · ↗ délégué à `cross-rbac-errors` · — non applicable.

## 5. Cas transverses (1 suite dédiée)

- **RBAC / ownership** : athlète n'accède pas aux écrans coach et inversement ; **cloisonnement multi-coach** (ADR-51) — un coach ne lit pas les groupes/athlètes d'un autre (P sur chaque GET sensible).
- **Erreurs réseau** : interception → 401 (refresh puis logout), 403, 404, 422 (messages de validation), 429 (rate limit), 500 (toast + retry).
- **Hors-ligne** : bandeau, brouillon auto-save de perf, synchronisation au retour réseau.
- **Consentement / gating** : `CONSENT_REQUIRED` sur données de santé.
- **Idempotence** : double POST perf / assignation (clé d'idempotence).
- **Navigation & deep-links** : back behavior, retour sur dernier onglet, routes masquées du tab bar accessibles directement.
- **États génériques** : chaque écran à requête → L, ∅, E+retry (déjà conventionnés : `*-loading/-empty/-error/-retry`).
